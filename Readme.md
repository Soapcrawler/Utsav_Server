# 🏭 Blast Furnace Guild — Vulnerable Factory Intranet
> **A Damn Vulnerable Industrial Web Server & CTF Training Lab**

An intentionally vulnerable, Windows 98–themed industrial factory intranet built with **Python (Flask)** and **SQLite**. Designed for cybersecurity education, penetration testing practice, and internal CTF (Capture the Flag) training — built for **Forge & Fracture**, UTSAV 2026's ACE Cybersecurity event.

## 🔎 Overview & Architecture

**Blast Furnace Guild** models a legacy manufacturing intranet terminal (styled in authentic Windows 98 theme) that manages steel smelting operations, shift handover logs, plant grievances, employee performance rankings, technical operating procedures, CCTV monitoring, live notices, and facility administration.

Behind its nostalgic interface lie web security vulnerabilities matching OWASP Top 10 categories, demonstrating how legacy architectures, missing authorization checks, and unvalidated input can lead to full compromise.

    BLAST FURNACE GUILD SECURITY LAB
    │
    ├── 01. SQL Injection (Auth Bypass)
    │   └── Route: POST /login                         (demonstration only — no flag)
    │
    ├── 02. SQL Injection (Search Filter)
    │   └── Route: POST /employee-corner                -> flag_001
    │
    ├── 03. IDOR (Confidential Profiles)
    │   └── Route: GET /profile/<id>                    -> flag_002
    │
    ├── 04. IDOR (Private Grievance Dispatches)
    │   └── Route: GET /grievances/view/<id>             -> flag_003
    │
    ├── 05. Path Traversal (Arbitrary File Read)
    │   └── Route: GET /document?file=<filename>         -> flag_004
    │
    ├── 06. Broken Access Control (Factory Control Center)
    │   └── Route: GET /admin                            (no flag of its own)
    │
    └── Bonus. Inspect Element
        └── CCTV page view-source                        -> flag_005

    Two extra, optional finds (neither required to reach the reward page):
      • A standalone bonus flag hidden in /robots.txt
      • The hidden reward page itself, unlocked once flag_001–flag_005 are found

## 🚀 Quick Start & Installation

### 1. Prerequisites
- **Python 3.8+**
- **pip**
- **SQLite3** (built into the Python standard library)

### 2. Setup Virtual Environment & Dependencies
From `deploy/vulnerable-factory-dashboard/`:

    cd deploy/vulnerable-factory-dashboard
    python -m venv .venv
    source .venv/bin/activate      # Windows: .venv\Scripts\activate
    pip install -r requirements.txt

### 3. Initialize or Reset the Database
Still inside `deploy/vulnerable-factory-dashboard/`:

    python database.py

### 4. Run the Web Server

    python app.py          # http://localhost:5000

> Make sure the venv is active (`which python` should point into `.venv/`) and that you're
> running `app.py` from inside `deploy/vulnerable-factory-dashboard/` — not from `deploy/`.

## 🎯 Security Challenges & Vulnerability Guide

### Challenge 01 — SQL Injection (Authentication Bypass)
- **Target:** `POST /login`
- Entering `admin'--` in the username field (any password) collapses the query's `WHERE` clause and logs you in as the first matching user. This challenge is a **demonstration of auth-bypass SQLi** and awards no flag by itself.

### Challenge 02 — SQL Injection (Employee Search Filter)
- **Target:** `POST /employee-corner`
- The `search` field is vulnerable to `UNION SELECT`. Listing tables via `sqlite_master` reveals a `vault_keys` table; pulling its contents returns **flag_001**.

### Challenge 03 — IDOR (Employee Profiles)
- **Target:** `GET /profile/<id>`
- Changing the numeric ID in the URL (e.g. `/profile/8`) loads another employee's profile. The admin's profile (id 8) exposes a private note containing **flag_002**.

### Challenge 04 — IDOR (Private Grievance Dispatches)
- **Target:** `GET /grievances/view/<id>`
- The server fetches a grievance by ID alone, without checking ownership. Viewing `/grievances/view/5` reveals a confidential grievance containing **flag_003**.

### Challenge 05 — Path Traversal (Factory Documents Archive)
- **Target:** `GET /document?file=<filename>`
- `GET /document?file=../flag.txt` escapes the `documents/` folder to read `flag.txt` (**flag_004**). Access is deliberately restricted to `documents/` and `flag.txt` only — attempts to read `app.py`, `database.py`, `factory.db`, or files outside the project (e.g. `/etc/passwd`) are blocked.

### Challenge 06 — Broken Access Control (Factory Control Center)
- **Target:** `GET /admin`
- The "Control Center" link is hidden from non-admin accounts, but the route itself enforces no check. Any logged-in employee who navigates to `/admin` directly sees the full control panel — all employees, badge IDs, salaries, and grievances. It awards no flag of its own (it re-exposes flag_002).

### Bonus — Inspect Element (CCTV Page)
- **Target:** `GET /cctv`
- **flag_005** sits in an HTML comment in the camera panel — visible via Inspect Element or view-source, not on screen.

### Optional — robots.txt
- **Target:** `GET /robots.txt`
- A standalone bonus flag, unrelated to flag_001–005 and **not required** to reach the reward page.

## 🎁 The Hidden Reward Page

Once a team has **flag_001 through flag_005**, concatenating them in order (no separators) and visiting that path reveals a hidden page:

    /{flag_001}{flag_002}{flag_003}{flag_004}{flag_005}

Any other path, or the flags out of order, returns a plain 404. The page is blank except for one image, one gif, and the text **"Congrats blud you did it."** Organizers drop their own files into `static/congrats/` as `congrats.jpg` and `congrats.gif`.

## 🛠️ Troubleshooting & FAQs

- **`ModuleNotFoundError: No module named 'flask'`** — your virtual environment isn't active for the Python you're running. Don't call an absolute interpreter path like `/bin/python`; activate the venv and just run `python app.py`, or run `.venv/bin/python app.py` explicitly.
- **`can't open file 'app.py'`** — you're one directory too high. `app.py` lives in `deploy/vulnerable-factory-dashboard/`, not `deploy/`. `cd` into it first.
- **Database looks empty or outdated** — re-run `python database.py` from inside `deploy/vulnerable-factory-dashboard/` to reseed `factory.db`.
